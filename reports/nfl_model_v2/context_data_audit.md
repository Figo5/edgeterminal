# QB, injury, and weather point-in-time audit

| Input | Current evidence | Permitted research use |
| --- | --- | --- |
| Announced starting QB / QB change | The historical schedule's starting-QB fields describe who actually started; they do not prove when an announcement was public. The current ESPN structured injury feed does not identify an announced starter. | Capture a dated team/league announcement with source URL, publication time if exposed, and retrieval time in `nfl_research_context_observations`. Do not infer an announcement from a final box score or depth chart. Prospective only for now. |
| QB availability | ESPN injury rows include player, team, position, status, source URL, and retrieval time, but the adapter has no original item publication time. | Detailed event snapshots append observed QB statuses before kickoff as `qb_availability`, marked `observed_only`. They do not modify the linear model or prior freezes. |
| Key offensive and defensive injuries | ESPN supplies structured statuses and positions when its feed responds. It does not provide a reliable original per-item timestamp in the adapter. Historical nflverse injury reports contain weekly records, but an archive's current contents or a date-modified field alone do not establish the value visible at each old kickoff; field availability differs by season. | Capture offensive and defensive statuses from live detailed event snapshots with retrieval time; retain raw position/status and source. No retrospective backfill until historical point-in-time release snapshots or publication records are audited. |
| Game-time weather forecast | Open-Meteo live forecast supplies retrieval time and the forecast hour (`valid_for`). The historical weather/reanalysis endpoint represents past conditions, not a pregame issued forecast. Open-Meteo's Single Runs archive preserves individual model runs with initialization times, but coverage depends on model and date. | Store outdoor game forecasts only when the forecast hour is within three hours of kickoff and retrieval preceded kickoff. Use archived run-specific forecasts only after confirming coverage and run time; do not replace a pregame forecast with observed weather. |

The ledger is append only and rejects post-kickoff observations and publication times after retrieval. A missing publication time remains explicitly `observed_only`, not an assertion that the underlying information first became public then. These prospective observations are kept separate from the historical training matrix and from the immutable weekly freeze. The current weekly board snapshot does not fetch injury or weather values; detailed event analysis is the capture path when those providers return data.

Sources: [nflreadr injury loader](https://github.com/nflverse/nflreadr/blob/main/R/load_injuries.R), [NFL injury-report policy](https://operations.nfl.com/media/2683/2017-nfl-injury-report-policy.pdf), [Open-Meteo Single Runs API](https://open-meteo.com/en/docs/single-runs-api), [Open-Meteo Previous Runs API](https://open-meteo.com/en/docs/previous-runs-api).
