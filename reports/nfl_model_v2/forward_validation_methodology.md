# Prospective NFL validation and market provenance

## Immutable research boundary

The linear candidate's 2026 Week 3 file, `forward_2026_week03.json`, is read only. Its SHA-256 is registered in `nfl_research_freezes`; the registry refuses a changed file under the same season, week, and family. Later weekly files are created exclusively before the first kickoff. They record the model and feature versions and hashes, input source hashes, training game count, projections, and observed prices when available. A week with incomplete prior scores or play data is refused. The live product remains PASS.

Run `python -m edgeterminal.nfl_forward_weekly` from the repository with its virtual environment. It attempts a new linear freeze only in the 36 hours before the first kickoff, refreshes the nflverse schedule and current-season play file, refreshes ESPN event identities, captures current ESPN quotes for the unstarted week's games, then grades due earlier freezes. The quote capture uses the ESPN adapter directly and cannot spend Odds API quota. Future freezes prefer those fresh, immutable quote rows and retain their row IDs, prices, books, and retrieval times; a missing market remains unavailable. It cannot overwrite an existing file. The API also invokes grading on startup and NFL refresh. Grading begins at least four hours after kickoff and requires an ESPN final with a mapped provider ID, matching canonical season/week/teams, nearby kickoff, valid integer scores, and a result retrieval timestamp after kickoff. Unmatched or nonfinal results stay pending.

`nfl_research_grades` stores revisions. A changed final score appends a new revision and an entry in `nfl_research_grade_audit`; old rows and the freeze cannot be updated or deleted through the database schema. Each grade retains the frozen prediction and quote, score, ATS/total/straight-up outcome, absolute errors, Brier contribution (ties excluded), and source/retrieval/grade times. ESPN does not expose an original "became final" timestamp in this adapter; `result_retrieved_at` is the time the final was first observed by this grader, not the time the game ended. Reports use the latest revision while preserving the full audit trail.

## Week 3 spread-field correction

The original Week 3 research file recorded `home_handicap` with the opposite sign from the home spread in the exact immutable live shadow quote. The file remains unchanged. A separate `nfl_research_market_freezes` sidecar links exact matching spread and total observations to their snapshot and quote IDs and recovers same-batch moneylines. `nfl_research_market_attestations` stores a SHA-256 of each source snapshot; the snapshot and attestation tables reject updates and deletes. Grading records both the raw file field and the actual observed home spread; ATS uses the latter. If an exact source quote cannot be recovered, ATS is unavailable rather than inferred. This correction was made before Week 3 outcomes and does not alter projections. The attestation proves the stored snapshot bytes from registration onward, not that ESPN's underlying price was executable or unchanged before retrieval.

## Market observations

Each `odds_snapshots` row stores normalized sportsbook and market, selection, line, American price, provider, retrieval time, kickoff, and quote phase. It is append only. ESPN's JSON property named `close` is parsed as an offer value; it does not establish that the offer was captured near kickoff. ESPN also lacks a reliable per-offer update time in the current adapter, so retrieval time is the earliest defensible observation time and may lag the underlying price.

A report calls a quote an **observed closing comparator** only when the same book, market, and side was fetched within 15 minutes strictly before kickoff. It does not claim an executable closing price. Otherwise closing-market comparison is unavailable. The separate `nfl_market_capture` command checks for mapped games in that window and, only then, fetches ESPN quotes; it makes no Odds API call. An every-15-minute quiet heartbeat runs that command while the weekly heartbeat refreshes ESPN game identities. A sleeping computer, missing mapping, absent ESPN offer, or stale underlying ESPN price still leaves an evidence gap. Opening quotes similarly require an actual timestamped opening observation; the current feed does not supply one. Multi-book ingestion uses the existing Odds API adapter; the fixture suite covers FanDuel, bet365, DraftKings, and Caesars aliases without any API request. Consensus is the median of fresh distinct-book spreads/totals and paired no-vig moneyline probabilities. Contradictory two-sided books are excluded. Consensus is research-only and is not a model feature.

The local runtime is set to ESPN-only odds while the last Odds API credit is preserved. Restoring quota permits multi-book collection through the same storage schema. Neither ESPN nor the current empty 15-minute close sample can support a claim of outperforming the executable market.

## Reporting

`forward_performance_2026.json` and `.md` are regenerated after grading. They show prospective results by family and week, edge bucket counts, paired observed-close comparisons, and deterministic game-level bootstrap 95% intervals. Sparse intervals are descriptive; games within a week are correlated. `research_results.json` is the separate retrospective development result and is never pooled into the prospective headline. No edge bucket becomes a pick threshold automatically.
