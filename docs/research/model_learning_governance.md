# Automatic model learning governance

`edgeterminal.model_learning_store` archives proposals and controls which one
serves future NBA or NFL research forecasts. It does not fetch data, train a
model, create official picks, or alter a saved forecast, selection, or grade.
The original fixed models remain the baseline when no approved artifact is
active. The user approved new, separately versioned learning cutoffs; original
version cutoffs and historical records remain immutable.

## Storage and integrity

Candidates contain a bounded, strict JSON envelope with the sport, version,
training cutoff, model parameters, source receipts, implementation hashes, and
paired validation rows. SHA-256 identifies the complete envelope. Source files
and implementation bytes are archived by digest under
`data/research/model_learning/`; file archives are written atomically without
overwriting existing bytes. Pickle and executable model deserialization are not
used. The normal serving code interprets the model's JSON parameters.

SQLite candidate and event tables reject updates and deletes. Activations,
rejections, and rollbacks append events, using an immediate transaction to
serialize decisions. A sport has one active version: the latest activation or
rollback event. Repeating a decision does not add another event; requesting
activation of an already rolled back version returns `retained` and leaves the
current version unchanged. Versions cannot be reused for different artifacts.

Serving verifies the envelope digest, fingerprint, metadata, archived code,
and current implementation hashes before returning an artifact. Missing or
changed artifacts raise an error. Full integrity checks also compare source
payload digests and the latest persisted quote/grade evidence. Neither a
corrupt artifact nor a failed candidate silently replaces the active model.

## Evidence and promotion

Promotion requires paired, sourced actual main lines, received before the
game, with final player results. NBA quotes and grades are checked against the
retained quote, lock, grade, game, and source tables. NFL checks retained main
line snapshots, capture payload digests, final grade evidence, and archived
official stat/final-game sources. A caller-supplied actual or line cannot
override those records. Pending and void results are ineligible; pushes are
excluded from decision metrics while their games remain excluded from training.

The outer validation games are disjoint from fitting, weight-development, and
calibration games. All fitting/tuning labels precede the recorded training
cutoff, calibration labels precede the calibration cutoff, and:

```
training_cutoff <= calibration_cutoff <= validation_start < validation_end
```

The trainers own chronological feature construction, lagged histories,
prevalidation source availability, candidate/baseline prediction replay, and
disjoint development/calibration splits. They archive those choices in the
artifact. The registry recomputes metrics from paired rows, rather than trusting
reported summaries. It cannot establish that an arbitrary caller's prediction
was generated by its claimed algorithm; production candidates must come from
the sport-specific trainers and their tested replay paths.

The fixed acceptance rules require at least 100 decided rows from 30 whole
games, and at least 20 rows from 10 games for every supported market. Each
market must have no increase in MAE, Brier score, or log loss. Aggregate Brier
score must improve by at least 0.002. The upper bound of the mean paired
game-level Brier difference (`mean + 1.96 * standard_error`) must be below zero.
This groups correlated props by game; it is an approximate uncertainty screen,
not a guarantee of future improvement. Calibration error is recorded as a
diagnostic. All inputs and derived metrics must be finite.

Validation must compare with the currently active candidate ID. A concurrent
promotion makes an older baseline comparison ineligible. A rejected proposal
leaves the active model in place and records its failure reasons. The outer
holdout must not be reused to tune the rejected proposal; trainers wait for
new validation games before a fresh scheduled attempt.

## Integration API

```python
register_candidate(sport, version, training_cutoff, artifact, evaluation,
                   sources, now=None)  # candidate metadata
gate(evaluation, training_cutoff, artifact=None, sport=None, now=None)
activate_if_passes(candidate_id, now=None)  # activated / rejected / retained
active(sport)              # metadata or None
load_active(sport)         # metadata plus artifact, or None
verify_active(sport, now=None)  # full integrity check, metadata or None
history(sport, limit=20)    # newest events first, no artifact bytes
rollback(sport, reason, now=None)
```

The parameters shown after `sources`, `artifact`, or `sport` in these simplified
examples are keyword-only in Python. `now` is UTC epoch seconds; omitting it
uses the current time. Metadata includes `candidate_id`, `version`,
`training_cutoff`, `fingerprint`, `artifact_sha256`, and validation evidence.
The worker performs the expensive full integrity check during diagnostics;
normal projection calls use the smaller `load_active` check.

Rollback follows the current candidate's approved predecessor, including an
explicit return to the original baseline for the first promotion. Each previous
artifact must pass full integrity checks before it can be restored. Invalid
predecessors are skipped with their IDs and reasons recorded in the rollback
event. If none qualify, the original baseline is restored. Repeated rollbacks
walk the approval chain instead of reactivating the version just removed. The
scheduler can roll back on verified integrity failures. A single
bad night or a small loss streak is not an automatic performance rollback rule;
any future performance rule needs adequate new, sourced forward observations.

## Source descriptors

Sources use `sha256`, `received_at`, and `role` (`training`, `calibration`, or
`validation`). Training/calibration receipts cannot exceed their cutoff.
Supported references are `nba_source_artifact` plus `id`,
`nfl_prop_grade_source_artifact`, `nfl_prop_raw_response` plus `batch_id` and
`page_number`, or `file` plus a repository-relative path within `data/nflverse`
or `data/research`. File modification time must support the claimed receipt;
subsequent checks use archived bytes so an upstream file refresh cannot erase
the model's training source.

These gates support a controlled learning process. They do not claim the
model continually wins, guarantee that a candidate will qualify, or turn
research records into official picks.
